# XcelerateAI Supabase Auth email templates

These are preserved production-readiness artifacts, not runtime backend assets. They contain no secrets, external images, or custom SMTP configuration.

## Current Phase 1 decision

Supabase's default development email delivery remains acceptable for the Phase 1 checkpoint. The current Free-project configuration does not provide the complete branded sender and hosted-template experience required by XcelerateAI, so these templates are intentionally not applied yet. This deferment is owner-approved and is not a Phase 1 blocker.

Do not add an SMTP provider, upgrade the Supabase plan, or purchase/configure a domain as part of Phase 1.

## Future production application procedure

After an XcelerateAI domain, DNS verification, and custom SMTP provider have been approved and configured:

1. Open the XcelerateAI Supabase project.
2. Go to **Authentication → Email Templates**.
3. Open **Confirm signup**.
4. Set the subject to `Activate your XcelerateAI Learning OS`.
5. Replace the message body with `confirm-signup.html`, then save.
6. Open **Reset password** (recovery).
7. Set the subject to `Reset your XcelerateAI password`.
8. Replace the message body with `reset-password.html`, then save.
9. Confirm **Authentication → URL Configuration** still includes the deployed site URL and allowed redirect URLs, including `http://localhost:5173/**` for local verification.
10. Send one confirmation and one recovery message to an owner-controlled test account. Confirm each button returns to the intended XcelerateAI route before production use.

Both templates use Supabase's documented `{{ .ConfirmationURL }}` variable. The link remains controlled and generated by Supabase Auth.

## Production readiness checklist

- Own and approve the XcelerateAI sending domain.
- Verify the required DNS records.
- Select and configure a custom SMTP provider.
- Configure a branded sender address.
- Apply `confirm-signup.html` and `reset-password.html`.
- Test confirmation and recovery delivery, links, redirects, mobile layout, and spam placement.

The built-in Supabase sender can expose provider branding or a provider-owned sender identity. Do not add an SMTP provider without a separate product, security, and operational decision.
