## Part A

### A2 — concept-scope reconciliation (run first, as required)

The spec suspected the M01W03-P01 contradiction was systemic. It is, and the cause is mechanical rather than editorial:

- **24/24 weeks** — every mission in a week carried *byte-identical* `conceptsUsed`
- **73/73 missions** — `skillFocus` was the week title, verbatim
- **24/24 weeks** — `conceptsUsed` was exactly the week title split on `,` / `and` / `/`

`conceptsUsed` had never been authored per mission. It was a tokenized week title stamped onto every mission in that week — which is why `"HTML/CSS Interface Structure"` became `["HTML","CSS Interface Structure"]`, why `"Month 1 Boss"` and `"Final Assembly: Elliot V1 Working Product"` appeared as *concepts*, and why M01W03-P01 claimed Functions for a build containing none.

**This is also the mechanism behind the 3.1 → 3.2 derailment.** Both missions inherited identical tokens, so no signal distinguishing them could exist in the data. The mission genuinely could not tell you its shape had changed.

**Fix applied:** `conceptsUsed` rewritten in place on all 73 missions from what each mission's own `requiredFeatures` / `stepByStepInstructions` actually exercise. This is the single mutation in this pass; it is safe because `conceptsUsed` is not progress-keyed (progress runs on `missionId`, step indices, resource titles, task indices), and the spec explicitly forbids the additive alternative — a parallel field would be the *"fourth voice in a disagreement instead of the fix."*

Verified: no week retains identical `conceptsUsed` across its missions; no week's `conceptsUsed` still equals its tokenized title; `"Month 1 Boss"` no longer appears as a concept anywhere; M01W03-P01 no longer claims Functions.

**B1 was bigger than the spec described.** Not a label bug: `PracticalMissionView.jsx` carried a hardcoded `knownFields` list predating V2, so *every* enrichment field fell through to a generic dump that printed raw keys with `uppercase` CSS inside a **collapsed** accordion. All that content was effectively invisible.

Fixed by giving the fields first-class rendering in three groups, plus a `FIELD_LABELS` map and `labelForField()` fallback so no raw key can reach the screen:

- **Before You Build** (Brief tab) — Background, Approach Outline, Scope Note
- **If You Get Stuck** (renamed tab) — Hints, Common Mistakes, Debugging Checklist
- **Going Deeper** (new tab) — Stretch Challenge, Thinking Prompts, Real-World Applications, Career Insight, Related Concepts, What This Unlocks Later, Commander Notes, Commander Mode

**A second instance of the same bug class, found and fixed:** `missionAdapter.js`'s `normalizeResource()` builds an explicit object and does **not** spread unknown fields — so `exactLocation`, `stopPoint`, `tier`, `formatType` would have been silently dropped before reaching any card, and B4 would have shipped as a no-op. Added additively; all default to `null`, so pre-V3 resources render exactly as before.

**Verified live in the running app** against your real curriculum: all three groups render with human-readable labels; resource cards show "START AT / STOP AT"; production build clean. The only console errors are pre-existing `validateDOMNesting` warnings in `PageHeader`, untouched by this pass.
